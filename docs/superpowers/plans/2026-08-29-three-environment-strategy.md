# Three-Environment Strategy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `npm run dev` always yield a working app — falling back to the deployed backend/socket per-service when the local one isn't running — and restore a production-usable multiplayer server.

**Architecture:** A `predev` probe script TCP-checks `localhost:8000` and `localhost:4000` and writes a gitignored `.env.local`; Vite's env precedence does the rest, so **no application code chooses URLs**. A dev-only badge warns when the app is wired to production data. The multiplayer server redeploys to Railway from its existing Procfile.

**Tech Stack:** Node 18+ ESM scripts, Vite env layering, React 19 + TypeScript, Django (settings unchanged), Railway, Docker Compose (optional Postgres).

**Spec:** `docs/superpowers/specs/2026-08-29-three-environment-strategy-design.md`

## Global Constraints

- **No app code chooses URLs.** `src/configurations/backend.tsx`, `src/socket.ts`, `src/utils/pool.ts` keep their current logic; only env values change.
- **Per-service resolution is required**, not incidental: local backend + remote socket (or the reverse) must work.
- `.env.local` is **generated output** — never read as input, never committed. It is already ignored by the `*.local` rule at `.gitignore:13` (verified with `git check-ignore -v`);
spec §7 lists a `.gitignore` entry under E0, but none is needed — do not add a duplicate.
- **Production URLs (exact):** backend `https://backend-kappa-one-42.vercel.app/api`; production frontend origin `https://nba-minigames.vercel.app`; dev-branch frontend origin `https://nba-minigames-git-dev-stefanromanpers-5412s-projects.vercel.app`.
- **Local ports:** Django `8000`, socket `4000`, Vite `5173`. QA ports (`8100/5273/4100`) belong to the pipeline — never reuse them here.
- Use `localhost`, never `127.0.0.1`: Vite may bind IPv6-only, making the literal IPv4 address unreachable.
- **`REMOTE_SOCKET_URL` starts as `null`** and is only set in Task 5, after the Railway deploy exists. Never point it at `nba-multiplayer-production.up.railway.app` — that host is dead.
- **Two owner-gated stages** (Tasks 4 and 5) change production and need billing/dashboard access. An implementer must **stop and hand over**, never attempt them.
- Per repo convention (`CLAUDE.md`): don't run lint/typecheck/build routinely — run them before committing.
- Commit style: conventional (`feat:`, `fix:`, `docs:`, `chore:`). Stage explicit paths; never `git add -A`.

## Task 1: The dev-env probe script

**Files:**
- Create: `scripts/dev-env.mjs`
- Modify: `package.json` (add `predev`)

**Interfaces:**
- Produces: `.env.local` containing `VITE_BACKEND_URL`, optionally `VITE_SOCKET_URL`, and `VITE_ENV_SOURCE_BACKEND` / `VITE_ENV_SOURCE_SOCKET` (each `local` or `remote`). Task 2's badge reads `VITE_ENV_SOURCE_BACKEND`.

- [ ] **Step 1: Write the script**

Create `scripts/dev-env.mjs`:

```javascript
/**
 * Picks backend/socket URLs for local development and writes .env.local.
 *
 * Run automatically before `npm run dev` (see package.json "predev"). Each service
 * is resolved independently: if the local port answers we use it, otherwise we fall
 * back to the deployed one. Vite gives .env.local the highest precedence, so no
 * application code participates in this choice.
 *
 * .env.local is generated output: gitignored, rewritten every run, never read back.
 */
import { writeFileSync } from 'node:fs';
import { connect } from 'node:net';
import path from 'node:path';

const REMOTE_BACKEND_URL = 'https://backend-kappa-one-42.vercel.app/api';

// null until a production multiplayer server exists again (see spec §4.2 / §5.5).
// Setting this is the ONLY change needed to enable the socket fallback.
const REMOTE_SOCKET_URL = null;

const LOCAL_BACKEND_URL = 'http://localhost:8000/api';
const LOCAL_SOCKET_URL = 'http://localhost:4000';

/** True if something accepts a TCP connection on the port. 300ms is plenty for loopback. */
function isPortOpen(port, timeout = 300) {
  return new Promise((resolve) => {
    const socket = connect({ host: 'localhost', port });
    const done = (result) => {
      socket.destroy();
      resolve(result);
    };
    socket.setTimeout(timeout);
    socket.once('connect', () => done(true));
    socket.once('timeout', () => done(false));
    socket.once('error', () => done(false));
  });
}

const [backendUp, socketUp] = await Promise.all([isPortOpen(8000), isPortOpen(4000)]);

const lines = [
  '# Generated by scripts/dev-env.mjs on every `npm run dev`. Do not edit or commit.',
];
const report = [];

// --- backend ---
if (backendUp) {
  lines.push(`VITE_BACKEND_URL=${LOCAL_BACKEND_URL}`, 'VITE_ENV_SOURCE_BACKEND=local');
  report.push(`  backend : LOCAL   ${LOCAL_BACKEND_URL}`);
} else {
  lines.push(`VITE_BACKEND_URL=${REMOTE_BACKEND_URL}`, 'VITE_ENV_SOURCE_BACKEND=remote');
  report.push(`  backend : REMOTE  ${REMOTE_BACKEND_URL}   *** PRODUCTION DATA ***`);
}

// --- socket ---
if (socketUp) {
  lines.push(`VITE_SOCKET_URL=${LOCAL_SOCKET_URL}`, 'VITE_ENV_SOURCE_SOCKET=local');
  report.push(`  socket  : LOCAL   ${LOCAL_SOCKET_URL}`);
} else if (REMOTE_SOCKET_URL) {
  lines.push(`VITE_SOCKET_URL=${REMOTE_SOCKET_URL}`, 'VITE_ENV_SOURCE_SOCKET=remote');
  report.push(`  socket  : REMOTE  ${REMOTE_SOCKET_URL}   *** PRODUCTION DATA ***`);
} else {
  // Write no VITE_SOCKET_URL: src/socket.ts already defaults to localhost:4000.
  lines.push('VITE_ENV_SOURCE_SOCKET=unavailable');
  report.push('  socket  : UNAVAILABLE — no local server and none deployed; multiplayer disabled');
}

writeFileSync(path.resolve('.env.local'), lines.join('\n') + '\n');

console.log('\ndev environment');
console.log(report.join('\n'));
if (!backendUp) {
  console.log('\n  Local writes will hit PRODUCTION data. Start the Django backend on :8000 to work locally.');
}
console.log('');
```

```json

```

## Task 2: The PROD DATA badge

**Files:**
- Create: `src/components/EnvBadge.tsx`
- Modify: `src/App.tsx`

**Placement note:** it goes in `src/components/`, next to `ModalHost.tsx` — **not** in
`src/components/ui/`, whose `index.ts` barrel is the game design system ("import these tiles when
building a new game UI"). A dev-only badge is not a design-system tile, so do not add it to that barrel.

**Interfaces:**
- Consumes: `VITE_ENV_SOURCE_BACKEND` from Task 1's `.env.local`.
- Produces: `<EnvBadge />`, a self-gating component — safe to render unconditionally.

- [ ] **Step 1: Write the component**

Create `src/components/EnvBadge.tsx`:

```tsx
/**
 * Dev-only warning that the app is talking to the production backend.
 *
 * Shown when `npm run dev` could not reach a local backend and fell back to the
 * deployed one (see scripts/dev-env.mjs) — writes from here reach real data.
 *
 * `import.meta.env.DEV` is statically false in a production build, so this whole
 * component is dropped at build time and can never ship.
 */
export default function EnvBadge() {
  if (!import.meta.env.DEV) return null;
  if (import.meta.env.VITE_ENV_SOURCE_BACKEND !== "remote") return null;

  return (
    <div
      style={{
        position: "fixed",
        bottom: 10,
        left: 10,
        zIndex: 9999,
        padding: "4px 10px",
        borderRadius: 6,
        background: "#b3261e",
        color: "#fff",
        font: "600 11px/1.2 system-ui, sans-serif",
        letterSpacing: 0.4,
        pointerEvents: "none",
      }}
      title="Local frontend is using the production backend — writes hit real data."
    >
      PROD DATA
    </div>
  );
}
```

- [ ] **Step 2: Mount it**

In `src/App.tsx`, add the import next to the existing `ModalHost` import (line 16):

Then render it inside the top-level `<MotionConfig>` shell, as a sibling of `<ModalHost />` (around line 54-64 — the return with `MotionConfig > BrowserRouter > MultiplayerProvider > ModalProvider`):

- **E3 (Task 5):** all three §5.5 checks pass — handshake responds, a room opens on the deployed frontend, probe reports `REMOTE`.
- **E4 (Task 3):** `docker compose config` resolves; the documented sqlite↔Postgres switch works.
