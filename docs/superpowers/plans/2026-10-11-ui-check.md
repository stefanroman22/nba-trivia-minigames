# UI Check System Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A deterministic Playwright check suite (guest / account / games / multiplayer × 7 viewports) plus Claude judge agents that turn its output into a findings report with fix instructions and machine-checkable acceptance criteria, and a fix loop in which the frontend/backend engines fix, verify and re-verify until each finding passes.

**Architecture:** `scripts/ui-check/` holds a `@playwright/test` project. Shared fixtures inject probes and expose an `audit` API that records rule violations with metrics and evidence crops. A custom reporter condenses all results into `digest.md`. Agents (`.claude/agents/ui-check-*.md`) only read the digest/crops and write findings JSON; `report.mjs` merges and validates them, `verify.mjs` re-runs any finding's acceptance criteria.

**Tech Stack:** Node ≥20 ESM (`.mjs`), `@playwright/test` pinned to the installed `playwright-core` (1.62.x), `axe-core`, Django `manage.py shell` (sqlite) for accounts, the existing Next.js 16 app, Socket.IO server.

**Spec:** `docs/superpowers/specs/2026-10-11-ui-check-design.md` — read it before your task; it is the authority.

## Global Constraints

- All runner code is plain ESM JavaScript `.mjs` under `scripts/ui-check/` (ESLint only lints ts/tsx; `next build` must not type-check these files). No TypeScript files there.
- `@playwright/test` version must equal the installed `playwright-core` version exactly (check `node_modules/playwright-core/package.json`). `axe-core` latest 4.x. Both devDependencies. Nothing paid.
- Invoke Playwright as `node node_modules/@playwright/test/cli.js test -c scripts/ui-check …` from scripts — never the `npx` string form (fails on this Windows setup).
- Browser: `channel` `'chrome'` on win32 (fallback `'msedge'`), bundled Chromium elsewhere — mirror `scripts/qa-browser.mjs#launchBrowser` logic; never hard-fail on a channel.
- Address servers as `http://localhost:<port>`, never `127.0.0.1`.
- Ports: prod mode Django 8200 / socket 4200 / Next 5374; dev mode 8000 / 4000 / 5173. Never kill a process the stack helper did not start.
- Django started by the runner always gets `DATABASE_URL=""` (sqlite) and `NBA_DEV_ENV_SKIP=1`. Logged-in personas refuse to run when the API host is not `localhost`.
- Viewport set, ids and sizes exactly as spec §2: `phone-360 360×720`, `phone-390 390×664`, `phone-414 414×715`, `tablet-768 768×954`, `tablet-1280 1280×720`, `desktop-1366 1366×657`, `desktop-1920 1920×969`; core = `phone-390`, `tablet-768`, `desktop-1366`. MP pairs: A `desktop-1366`+`phone-390`, B `phone-360`+`desktop-1920`, C `tablet-768`+`tablet-1280`, D `phone-414`+`phone-390`.
- Accounts: `testuser1`, `testuser2` (multiplayer pair), `testuser3` (solo); emails `<username>@uicheck.test`; secrets only in git-ignored `.ui-check/accounts.json`.
- Check IDs appear in test titles as `[ID] description`; prefixes `G-` guest, `AC-` account, `GM-` games, `MP-` multiplayer, `ST-` selftest, `ACCEPT` acceptance. Each ID exactly once across specs and documented in `scripts/ui-check/CHECKS.md` (generated families documented as patterns).
- Evidence screenshots: JPEG quality 70, `scale: 'css'`, crops padded 16 px; full-viewport shots only at named states.
- Never modify app source (`src/`, `backend/`, `multiplayer_server/`) in Tasks 1–8 except where a task explicitly says so. If a check reveals an app bug, the check stays strict and the bug is noted in your report — the judges turn it into a finding later.
- Commit messages: one short plain line, NO `Co-Authored-By` or any AI attribution trailer.
- Do not run `npm run build`/lint/tsc routinely (project rule); do run the specs you write.

## Review Focus

1. Local stack not running / partially running (e.g. Django up, socket down) → stack helper starts only the missing services and stops only those at teardown.
2. Parallel contexts for the same account (games suite workers) → each context gets its own minted token pair; nothing logs another context out.
3. A detector that fires on everything (e.g. `occluded` on elements under the sticky nav after scroll, `snap` on intentional instant feedback) → selftest pages prove both bad-fires and good-stays-quiet; specs pass `ignore` for documented exemptions.
4. A game adapter that cannot know the correct answer → scenario becomes a string reason listed as a coverage gap, never a silently passing test.
5. An acceptance criterion that already passes on unfixed code → `report.mjs --validate` rejects it.

```
# UI check digest — run <id> · mode <prod|dev> · <n> tests · <m>m<s>s
| suite | pass | fail | skip |
## FAIL <checkId> <title>
- <rule> `<selector>` on <route>: <measured> (expected <expected>) — <vp list> — shot: <first shot rel path>
```

Hard cap: digest ≤ 400 lines; overflow lines summarised as "+N more (see results.json)".

### Task 9: Findings schema, acceptance DSL, verify, probe, report

**Files:** Create `scripts/ui-check/findings.schema.json`, `lib/findings.mjs` (load/validate/merge/fingerprint/dedupe), `specs/accept/accept.spec.mjs` (project `accept`, reads assertions from `UI_CHECK_ASSERT_FILE`), `verify.mjs`, `probe.mjs`, `report.mjs`, `accepted.json` (`[]`), `fixtures/findings/sample.json` + `specs/selftest/findings.spec.mjs` (`[ST-FINDINGS]`, `[ST-REPORT]`).

**Acceptance assertion DSL (exact):**
```json
{ "persona": "guest|solo", "viewport": "<viewport id>", "route": "/path",
  "steps": [ {"click":"<loc>"}, {"fill":["<loc>","text"]}, {"press":"Escape"}, {"hover":"<loc>"},
             {"waitFor":"<loc>"}, {"wait":300}, {"scroll":"bottom|top|<px>"} ],
  "watch": ["<css>"],
  "expect": [ {"visible":"<loc>"}, {"hidden":"<loc>"}, {"count":["<loc>",">=|<=|==",1]},
              {"text":["<loc>","substring"]}, {"noOverflow":true}, {"withinViewport":"<loc>"},
              {"minSize":["<loc>",44,44]}, {"style":["<loc>","prop","value"]},
              {"transition":["<loc>","prop"]}, {"noSnap":true}, {"maxCls":0.1}, {"maxLoafMs":100},
              {"status":["urlRegex",403]}, {"url":"regex"}, {"noConsoleErrors":true}, {"axe":["rule-id"]} ] }
```
`<loc>` = Playwright selector string (`role=button[name="Log in"]`, `text=…`, CSS) or `@area.key` (pagemap).

**CLIs:**
- `verify.mjs <findingId…> [--run <id>] [--mode dev|prod] [--expect-fail] [--mark]` — per finding: runs `acceptance.checks` (`-g` regex of ids, `--project` list) and `acceptance.assertions` (accept project); prints `PASS|FAIL <id> — <first failing line>`; exit 0 iff all pass (with `--expect-fail`: iff all FAIL). `--mark` sets `status:'fixed', fixedAt` in `<runDir>/findings.json` and regenerates `REPORT.md`.
- `probe.mjs --assert '<json>' | --assert-file f [--mode]` — runs one ad-hoc assertion, prints ≤ 20 lines plus one crop path (judges' confirmation tool).
- `report.mjs [--run <id>] [--validate]` — merges `<runDir>/findings/*.json`, validates against the schema, dedupes by fingerprint (merges viewports/evidence), drops `accepted.json` fingerprints, with `--validate` runs `verify --expect-fail` on each and moves non-reproducing findings to `<runDir>/rejected.json` with the reason; assigns ids `UIC-<runId>-NNN`; writes `findings.json` and `REPORT.md` (summary tables by severity × owner × suite; coverage matrix from `results.json` — check × viewport pass/fail/skip; coverage gaps; then each finding: Title, severity/owner/category/viewports, **Current**, **Expected**, **Evidence** (metrics, shot links), **Files** (path:line — why), **How to fix** (Change / Reuse / Build / Rules), **Acceptance criteria** (bullets + the exact `node scripts/ui-check/verify.mjs <id>` command)).
