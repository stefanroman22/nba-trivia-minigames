# Design: seo-a11y-pass

Task: "Technical SEO + full keyboard and ARIA accessibility pass" (Category frontend, P1). Technical
only — no copy, content, visual or design changes. Scope per card: per-page meta (title, description,
canonical, Open Graph, Twitter), JSON-LD, a real `sitemap.xml`, Core Web Vitals / Lighthouse fixes,
and full keyboard + ARIA operability across the app (Tab / Shift+Tab / Enter / Escape / arrows,
visible focus, correct roles, no traps). Audit first, then fix what the audit found. `public/robots.txt`
and `public/llms.txt` are separate pending cards — untouched here.

Classify: hard / frontend + ui + games / risk low. Design round 2026-09-30, planner on fable.
Branch `team/seo-a11y-pass` (cut from `origin/dev` dccfbfb). Cloud run.

## Decision summary

**Engine: sonnet** — 16 steps, each with exact files, exact markup/attributes/handlers and a
done-check. Every judgment call (which ARIA pattern, which keys do what, where focus goes, which
schema, which URL is canonical, which perf flags) is settled below; nothing is left for the build to
design. No step changes any motion (the SegmentedTabs thumb, the drawer slide, the Stage cross-fade
and Modal transitions are all untouched — only attributes and handlers are added), so the motion →
opus rule does not fire, and opus is banned for this run anyway. Pipeline budget is ~60 min end to end;
the plan is bounded accordingly (see "Not planned").

**Seats.** This cloud session has no `Agent` tool and `ListAgents` shows no engine teammates (same as
the 2026-09-20/22/23 cloud rounds), so the single `frontend-engine` proposal seat was filled by the
planner from source, and the sign-off pass is the 5b self-review at the end of this doc. There is no
backend half.

### Decisions

**D1 — One site-URL source: `src/configurations/site.ts`.** `SITE_URL` = `NEXT_PUBLIC_SITE_URL` if set,
else `https://${VERCEL_PROJECT_PRODUCTION_URL}` (Vercel system env, always the production domain even
on `dev` previews — which is the correct canonical for a preview), else the documented production
origin `https://nba-minigames.vercel.app`. Trailing slash stripped. Every absolute URL (canonical, OG,
JSON-LD, sitemap) derives from it. The `NEXT_PUBLIC_SITE_URL` override is documented in
`docs/DEPLOYMENT.md` (env table). The hard-coded last fallback is the site's own public origin, not a
service URL or secret — recorded here so review does not flag it against the "URLs come from env" rule.

**D2 — Metadata shape.** Root layout adds `metadataBase`, `alternates.canonical: "/"`, `openGraph`
(type website, siteName, locale `en_US`, the logo as image) and `twitter` (card `summary` — the logo is
160×159, too small for `summary_large_image`). Game pages override `alternates.canonical`, `openGraph`
(type website, url, title, description, the game's own art 720–800 px wide → `summary_large_image`) and
`twitter`. `/admin` keeps its noindex; `/coming-soon` gains `robots: { index: false }` (404s are auto-noindexed by Next).
Titles/descriptions are the existing catalogue strings — no copy changes.

**D3 — JSON-LD.** Home: `WebSite` with `publisher: Organization` (name, url, logo). Game page:
`VideoGame` (a schema.org subtype of both `Game` and `SoftwareApplication`, so it satisfies the card's
"Game or SoftwareApplication") with name, description, url, image, genre "Trivia", `gamePlatform`
"Web browser", `applicationCategory` "GameApplication", `operatingSystem` "Any",
`isAccessibleForFree: true`, a free `Offer`, and the same publisher. Rendered by one tiny server-safe
component, `<`-escaped per the Next JSON-LD guide.

**D4 — Sitemap.** `src/app/sitemap.ts` (`MetadataRoute.Sitemap`): `/` (priority 1, weekly) + every
`visibleGames` entry except `coming-soon` (priority 0.8, weekly). No `/admin`, no `/coming-soon`, no
hidden games. `lastModified` omitted (no per-game date exists; a fake one is worse than none).

**D5 — LCP image on game pages: React 19 `preload()` from the server page.** `[game]/page.tsx`
calls `preload(art, { as: "image", fetchPriority: "high" })` with the game's art URL, which emits
`<link rel="preload" as="image" fetchpriority="high">` in the SSR head so the idle thumbnail
(the measured LCP element) is discovered with the HTML instead of after CSS + hydration. The art URL
comes from a new `backgroundUrl()` helper in `GameUtils` that `GameTile` also switches to (it inlines
the same regex today — reuse-first).

**D6 — `experimental.inlineCss: true`.** Six tiny stylesheets (~24 KiB total) become `<style>` in the
head — the documented remedy for exactly this render-blocking pattern with Tailwind + small hand CSS.
Trade-off accepted: returning visitors re-download ~24 KiB of CSS per navigation. Guard: if `next
build` fails or the page renders unstyled with the flag, the step is reverted and noted; nothing else
depends on it.

**D7 — Drawer becomes a modal dialog using the trap Modal already has.** The Escape/Tab-trap/initial
focus/restore logic in `src/components/ui/Modal.tsx` is lifted verbatim into
`src/hooks/useFocusTrap.ts` and used by both `Modal` (behaviour identical, incl. scroll lock) and the
drawer (`lockScroll: false` so the drawer's current scrolling behaviour is unchanged). Drawer panel
gets `role="dialog" aria-modal="true" aria-label="Menu"`; hamburger gets `aria-expanded` +
`aria-controls`; the trap's restore returns focus to the hamburger on close.

**D8 — Brand is a link.** `div.nav3-brand onClick` → `<a href="/" className="nav3-brand">` with
`onClick={(e) => { e.preventDefault(); goHome(); }}` so the page transition and the leave-match logic
are preserved, while the element is focusable, has a native role, works with Enter and middle-click,
and is an internal link crawlers can follow. `.nav3-brand` gets `color: inherit; text-decoration:
none;` so it renders exactly as before.

**D9 — Tabs: roving tabindex + arrow keys, automatic activation, one hook.**
`src/hooks/useRovingTabs.ts` returns a `tablist` keydown handler (ArrowRight/ArrowDown → next,
ArrowLeft/ArrowUp → previous, both wrapping; Home/End) that selects **and** focuses the target tab
(automatic activation — these switchers swap content instantly today, so selection-follows-focus
matches the existing mouse behaviour). The selected tab has `tabIndex={0}`, the rest `-1`, so a
tablist is one Tab stop. Used by `SegmentedTabs` (5 callers, no prop changes) and by Admin's
hand-rolled tabs (kept hand-rolled — wrapping them in `SegmentedTabs` would add the sliding thumb,
a visual change).

**D10 — Autocomplete becomes a WAI-ARIA combobox (list autocomplete, managed focus stays in the
input).** Roles/ids/`aria-activedescendant` as specified in step 12. Keys: ArrowDown/ArrowUp move a
highlight (wrapping; ArrowDown with nothing highlighted → first, ArrowUp → last), Enter with a
highlight → fills the input with that option and closes the list (exactly what a click does today —
it does **not** submit; a second Enter submits, as today), Enter without a highlight → existing
submit, Escape → closes the list (text kept), Tab → closes the list and moves on. Hover sets the same
highlight, replacing the two inline `style.backgroundColor` mutations with state — the highlighted
row uses `suggestionItemHoverStyle.backgroundColor`, so the look is unchanged. Props are unchanged; the
12 callers are not edited.

**D11 — Focus handoff on stage changes.** `.playing-wrap` gets a callback ref that focuses the first
focusable inside it on mount (`preventScroll: true`) — that div mounts exactly when the playing phase
finishes its cross-fade in, so the timing problem of "the new phase isn't in the DOM yet when
`stage` changes" is sidestepped. `GameResult`'s "Play again" gets `autoFocus` (that component never
mounts on page load, so no focus steal on first paint). Idle on first load is deliberately not
focused (no autofocus on page load).

## Risks

- `experimental.inlineCss` is experimental — mitigated by the explicit revert rule in step 7.
- `VERCEL_PROJECT_PRODUCTION_URL` requires "Automatically expose System Environment Variables"
  (Vercel default on) — mitigated by the production-origin fallback (D1).
- `useFocusTrap` with an unstable `onClose` would re-run the effect every render and re-focus the
  first element — step 9 pins `useCallback` in Navigation; `Modal` already receives the stable
  context `close`.
- `aria-activedescendant` on the input requires option ids to be unique per instance — `useId()` per
  component (step 12).
- Tab-key handling inside `AutocompleteInput` must not `preventDefault` (Tab must still move focus).
- `autoFocus` on "Play again" also fires in the multiplayer result path if `GameResult` is reused
  there — acceptable (same intent), but the QA pass checks the single-player flow only.

export function useFocusTrap(ref: RefObject<HTMLElement | null>, onClose: () => void,
  { active = true, lockScroll = true }: { active?: boolean; lockScroll?: boolean } = {}) {
  useEffect(() => {

### 11. `[sonnet]` Roving tabs — `src/hooks/useRovingTabs.ts` (new), `src/components/motion/SegmentedTabs.tsx`, `src/views/Admin.tsx`
Hook:
```ts
export function useRovingTabs<T extends string>(keys: readonly T[], value: T, onChange: (key: T) => void) {
  const onKeyDown = (e: KeyboardEvent<HTMLElement>) => {
    const i = keys.indexOf(value); const last = keys.length - 1; let next = i;
    if (e.key === "ArrowRight" || e.key === "ArrowDown") next = i >= last ? 0 : i + 1;
    else if (e.key === "ArrowLeft" || e.key === "ArrowUp") next = i <= 0 ? last : i - 1;
    else if (e.key === "Home") next = 0; else if (e.key === "End") next = last; else return;
    e.preventDefault();
    onChange(keys[next]);
    e.currentTarget.querySelectorAll<HTMLElement>('[role="tab"]')[next]?.focus();
  };
  return { onKeyDown, tabIndexFor: (key: T): 0 | -1 => (key === value ? 0 : -1) };
}
```
