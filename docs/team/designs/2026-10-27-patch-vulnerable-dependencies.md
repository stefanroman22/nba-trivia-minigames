## 4. Risks
- **Shared-DB migrate on the dev push** (BE-6, BE-20): the dev backend preview build runs `migrate` on production Supabase
  with Django 5.2 / DRF 3.18. Prevented by step 9: `makemigrations --check --dry-run` clean and `showmigrations --plan`
  byte-identical before/after the upgrade (contrib apps `admin auth contenttypes sessions token_blacklist` included). If
  the plan differs, the card stops (fix-loop message names the new migration) — nothing is pushed.
- **Supabase PostgreSQL < 14 would make Django 5.2 refuse the connection.** UNVERIFIED from the sandbox (no DB access).
  Blast radius if it is 13: the dev backend preview build fails loudly at `migrate`; production (still 5.1) is untouched.
  Listed as owner pre-check in §7; Supabase has shipped PG ≥ 15 for years, so the plan proceeds.
- **sweetalert2 11.6.13 → 11.26.25 visual drift** (`src/utils/Alerts.tsx`, `src/utils/GameUtils.tsx:29-46`,
  overrides in `src/styles/LandPage.css:422-455`; `src/components/GameCard.tsx:20-29`'s inline-styled popup is unreachable today —
  GameCard is rendered only by `src/views/Admin.tsx` without `gameStarted`). No baseline
  shot run exists in the cloud, so the proof is gate 2's Swal flow (§5) judged by browser-qa; fallback in step 12 is to
  pin `sweetalert2` to the lowest unaffected version (`^11.6.14`; the advisory range is 11.4.9–11.6.13) and record why.
- **styled-components 6.6.0** only re-hashes class names of `src/components/Loader.tsx`'s static wrapper; nothing selects
  them. Covered by `npm run build` + smoke.
- **npm 11 pruning nested deps** so CI `npm ci` fails: prevented by the npm-10 rule and the lock-diff done-check in
  step 2 (no removed `puppeteer-core/node_modules/*` / `proxy-agent` entries) plus `rm -rf node_modules && npm ci`.
- **The check stack silently tests old code**: `backend/.venv` and `multiplayer_server/node_modules` resolve to the
  main checkout's (symlink or `venvPython` fallback in `scripts/team/verify.mjs`/`qa.mjs`). The plan upgrades that venv
  in place (step 8; the orchestrator allows it) and installs the relay's node_modules in the worktree (step 6), so gate
  1/2 run the new Django/DRF and the new relay lock.
- **Python version skew**: the venv is Python 3.11 (`backend/.python-version` says 3.12, Vercel builds 3.12, GitHub jobs
  3.13). Django 5.2 and DRF 3.18 support 3.10–3.13, so the suite result transfers; recorded in `build-report.assumed`.
- **Next 16.3.4 → 16.4.3**: no App Router breaking changes; `agentRules`/`experimental.inlineCss` remain valid; React
  19.3 bundled; CSS-module class shortening irrelevant (0 `*.module.css`). Caught by `tsc` + `next build` (all `[game]`
  pages and OG/Twitter images prerender) + smoke. New build warnings are recorded, not fixed.
- **Protocol**: socket.io-client 4.8.4 and server 4.8.1 both speak Socket.IO v5 / Engine.IO v4; the relay sends no
  binary and caps frames at 16 KiB. Proven by the relay suite (`npm test --prefix multiplayer_server`), which drives the
  relay with the root (upgraded) client.
- **Remaining known findings after this card** (documented, not fixed): 13 high in the dev-only `@lhci/cli`/
  `lighthouse@12` tree (no upstream fix, `npm audit --omit=dev` is clean); relay `body-parser` is fixed although
  unreachable; moderation service keeps its last-built Pillow until the owner redeploys it.
